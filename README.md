# 调查解谜游戏框架（数据驱动 + 编辑器/玩家分离）

一个"旧档案 × 未来终端"风格的调查解谜网页。所有内容都在网页编辑器里创建、保存草稿、发布；玩家端只读取已发布内容，不含任何写死的题目或答案。

## 后端

启用 Lovable Cloud 作为持久化存储：章节、档案、地图、地点、证据、问题、验证规则、全局设置各自一张表，都带草稿/发布状态与发布快照。玩家端只读已发布数据；编辑端读写全部。

## Phase 1 — 数据架构与持久化
- 建表 + 权限：stages、files、maps、locations、evidence、questions、verifications、settings
- 每条内容有 status（draft/published）、排序、关联字段（档案↔地点、证据↔档案、问题↔证据）
- 发布动作把草稿内容写入发布版本，玩家端只读发布版本

## Phase 2 — 路由与模式分离
- `/` 玩家端入口（初始化流程 → 主界面）
- `/editor` 编辑端（与玩家端完全独立的布局与数据通道）
- 玩家端不引入任何编辑代码路径；编辑端提供 Preview as Player

## Phase 3 — 玩家端（桌面三栏终端界面）
- 左栏：档案检索（关键词/编号搜索、结果列表）
- 中栏：档案阅读器 / 地图浏览（地点热点可点击）
- 右栏：证据板（收集到的证据、笔记）
- 初始化流程：终端启动动画 + 简报 → 进入章节
- 判断/验证：提交答案由后端规则校验，只返回"通过/不通过"与作者写的提示，绝不提前显示答案或自动推理

## Phase 4 — 编辑端（表单化内容管理）
Stage、File、Map（地点对象增删与拖动定位）、Location、Evidence、Question、Verification、Settings 各一套列表 + 表单，含保存草稿、发布、删除、关联选择器，以及 Preview as Player。

## Phase 5 — 内容录入（通过编辑器写入数据）
- Stage 01：8 份普通档案、4 张地图、候选 HOUSE A–D、对应地点/证据/问题/验证
- Stage 02：仅作为解锁后的占位标题

## 技术细节
- TanStack Start 路由 + 服务端函数读写数据库；玩家端读取走公开只读通道，编辑端与验证走受控服务端函数
- 验证答案只存服务端并通过服务端函数比对，永不下发到浏览器
- 视觉：暗色 CRT 终端底 + 泛黄档案纸质感，等宽字体做终端、衬线体做档案

## 需要你确认
- 编辑器是否需要登录保护（默认：先不加登录，任何人打开 `/editor` 都能编辑）
- 具体的 8 份档案 / 4 张地图 / HOUSE A–D 文本内容：若你不提供，我会先写入结构完整、语气统一的占位剧情文本，你随后在编辑器里改。
